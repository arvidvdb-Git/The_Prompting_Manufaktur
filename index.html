Application instructions

System Prompts

Configure stable behavior once. Supply the task and evidence separately.

A system or developer instruction defines persistent application behavior: purpose, evidence standards, response conventions, and handling of uncertainty. A user message supplies the current request. The exact roles and precedence depend on the platform; naming a paragraph “SYSTEM” inside a user prompt does not promote its authority.

Configure the assistant

In an API, use the documented system/developer configuration field. In a custom assistant, use its instruction settings. Ordinary chat users may only have custom instructions or a reusable opening brief; those are product features, not a guarantee of system-level control.

Optimize the behavior

Keep stable rules short and testable. Move changing specifications into supplied context or retrieval. Version the configuration, test ordinary and conflicting requests, inspect failure cases, and retest after model changes.

Trusted application configuration→Authorized user task→External evidence as data

Simplified trust relationship, not a universal vendor role specification. Permissions, secret storage, and action authorization must be enforced by the application.
